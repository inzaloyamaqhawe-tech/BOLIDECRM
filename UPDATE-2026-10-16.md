# Xneelo upload: 16 October 2026

The configured Xneelo database was backed up privately and migrated directly. All 36 real leads and seven existing accounts were preserved. Temporary integration-test records were removed. No SQL import is needed for this update.

Upload individual files from `app/deploy-crm` into the existing website `crm` folder. Close CRM tabs during the upload and reopen after all files are in place. No ZIP is needed; do not create a nested deploy-crm folder.

1. Upload `api/workflow.php`, `api/import-functions.php` and `api/state.php` into `crm/api/`.
2. Upload all files inside `deploy-crm/assets/` into `crm/assets/`.
3. Upload `reminders-sw.js` into `crm/`.
4. Upload `index.html` into `crm/` last.

Keep the existing `api/config.php`, `.htaccess` and other unchanged files. Do not upload database scripts, source, private backups or tests. The exact generated asset names are listed in `deploy-crm/UPLOAD-FILES.txt`.

Open https://bolide.co.za/crm/ and refresh with Ctrl+F5 after uploading. Sign in, click **Enable Windows notifications**, then allow browser notifications. Valid HTTPS, browser permission and an open or minimised CRM tab are required. Closed-browser push is not configured. Only the assigned person receives a task reminder. The in-app reminder bar remains available when desktop notifications are blocked by the browser or Windows.

All production inputs save through the PHP API to MySQL: assignments, priorities, reminder times, recurrence links, next actions, deadline changes/reasons, escalation recipients, KYC documents/status/verification/expiry, signature details and personal saved views. Wait for **All changes saved** before closing the page. The static GitHub preview still saves changes only in the current browser and does not connect to Xneelo.

Existing imported active leads are flagged until a next action is entered. Saving an active deal requires an action, responsible person and due date. Inactivity flags use a 14-day threshold.

The starter KYC checklist contains company registration, authorised signatory identity and business address. Additional required documents can be added. Save new deals before uploading attachments. Open the KYC checklist, select supporting files and verify the documents before progressing to a proposal. Imported proposal-stage deals remain editable; subsequent progression checks the checklist. Expired required documents block progression.

Won requires a signature date (today or earlier) and a selected signed final proposal attachment. Monthly Won counts use the signature date.

Recurring follow-ups create the next occurrence when completed. Re-completing an occurrence does not create another duplicate. Reminder times are entered in South African time. Proposal deadlines exclude weekends and South African public holidays, including observed Mondays and known proclaimed holidays. Calendar reference: https://www.gov.za/about-sa/public-holidays. Newly proclaimed dates must be added to `src/lib/proposal.ts`.

Field history is under Reports and records the signed-in account, timestamp, field, previous value and new value. Production history is generated and preserved by the server. Historical before/after values start with this update; previous values from earlier edits cannot be reconstructed.

Validation completed: TypeScript and both production builds; deadline/contact/workflow regression tests; PHP syntax checks; temporary-record API tests against Xneelo; Chromium UI checks with simulated desktop notifications to verify task-recipient isolation.
